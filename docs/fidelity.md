## Acceptance boundary

Rust tests check our state model. Window smoke tests check that actual winit/wgpu frames can be presented and that these routes render. Neither proves parity with the physical phone. Handset screenshots remain separate from replica screenshots in `docs/images/`.

The owner has narrowed acceptance to useful, faithful phone interaction rather than exhaustive reconstruction. See the [delivery scope](remaining-work.md). The earlier 5–10 day estimate has been withdrawn. Prioritize the local message lifecycle, core navigation and targeted layout checks; actual local music playback is now required, using the selected in-process VFS. Service-dependent flows need explicit test fixtures. Unknown native behavior must remain marked unknown; adding a plausible host implementation does not resolve it.

Current priority is the supported basic phone applications. Complex web compatibility is outside the requested scope; basic browser controls and text-page behavior still need accurate comparison.
