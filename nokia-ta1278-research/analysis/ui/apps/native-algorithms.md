# 本机算法补充

本轮继续分析已有系统 `user.bin`，没有连接手机、读取私人存储或运行固件。输入 SHA-256 为 `8f0db2dc82f9e763cb700c2e5781b7ca7125a4d250f4c075dbec793eb549c1ca`。地址减去 `88000000` 就是文件偏移。

原生数值、条件和跳转为 A；跨版本名称为 B。可直接测试的小规则在 [native_app_rules.py](../../../tools/native_app_rules.py)。它们只覆盖下述函数边界，不能代替完整应用、基带或网页引擎。现有 `app_interaction_reference.py` 的文件夹、历史、网络结果等策略仍标 P。

## 短信容量和编码

`88b50d34` 从 alphabet、r3 和两个上下文字节选择容量。表中的单位是**已经编码的内容单位**，不是屏幕显示字符数。`r1` 指向多段容量，`r2` 指向单段容量，均写一个字节。

| alphabet | r3 额外头标志 | 语言标志 +2c | 单移位标志 +2d | 单段 | 多段 |
|---:|---|---|---|---:|---:|
| 0 | 0 | 0 | 任意 | 160 | 153 |
| 0 | 0 | 1 | 0 | 155 | 149 |
| 0 | 0 | 1 | 1 | 155 | 146 |
| 0 | 非零 | 任意 | 任意 | 154 | 146 |
| 1 | 0 | 任意 | 任意 | 140 | 134 |
| 1 | 非零 | 任意 | 任意 | 133 | 127 |
| 2 | 0 | 任意 | 任意 | 140 | 134 |
| 2 | 非零 | 任意 | 任意 | 133 | 128 |

容量来自 MOVS 立即数，生成脚本核对指令编码后提取。两个上下文字节位于 `81d16394+2c/+2d`；r3 由调用方的发送上下文 `+153a` 取得。名称“语言/单移位”为 B；标志来源和数字为 A。**不可把额外头标志直接等同于用户某个设置。**

`883d92f4` 的正文转换明确保存 alphabet 至对象 `+10`。alphabet=2 路径按 `min(UTF-16 单元数×2,804)` 记录字节长度并复制内容；与公共源码的 UCS2 路径相符。alphabet=0/1 与默认字母表/8-bit 关联为 B。UI 的 70/67 初始化、顶部格式和字符分类已在 [交互内核](interaction-core.md) 恢复，设备当前设置仍未知。额外头单段值 **133** 是本机立即数，不能为了符合通用公式将它改成 132。

分段 helper `88b50ea2..88b50ed0` 先取剩余长度和容量较小值；若 alphabet=0 或 1，所选段最后一个编码字节是 `1b`，长度减一。这证明 ESC 不落在该段尾；没有证明整个字符转换表或 UI 计数算法。`sms_segment_size` 只复现这一局部规则，调用者仍负责选择容量和已有段偏移。

机器结果：[sms-encoding-rules.json](sms-encoding-rules.json)。正文转换、分段、容量反汇编均在 `code-index.json` 中有范围 SHA。

## 短信重试和发送完成

`883c5e68` 是只含整数比较的重试原因判断。对 0…65535 的比较树静态求值，只有以下 19 个 `rl_cause` 返回真：

`11, 17, 21, 22, 27, 36, 38, 41, 42, 47, 61, 81, 95, 96, 97, 98, 99, 111, 255`

这是网络失败原因字段，**不是** `sms-operation-status.json` 中的 UI 提示编号。未核对本机协议枚举的原因码保留数字。

错误确认函数 `883c407e` 的顺序：

1. 取不到发送对象，或 cause=0：记录日志并返回。
2. cause=4/9：写 send_result=2，进入不重试 helper，finish_flag=0。
3. 其他 cause：只有剩余重试字节大于零，且 rl_cause 在上表，才将次数减一，写 result=2、send_status=2，转入 `883c4030`。
4. 其余进入不重试 helper，finish_flag=1。

`883c4030` 还要求当前对象存在、对象 `+1508 == 3`、`883c242a` 返回非空，才调用 `880c8a02`。因此“进入重试分支”不等于立即再发。公共源码的 MINI 分支有 5000 定时器；**本机这一错误分支直接调用 continuation**。发送等待窗口也有 timer 路径和日志，不能由此推断全固件没有重试定时器。

发送成功函数 `883c3986`、错误保存 `883c3d0c`、写入确认 `883c435e` 分别处理；它们会检查分段、已保存记录和发送上下文。写入确认比较状态 1/3/4/5 并按条件发送下一段或完成。仍未恢复所有状态组合、初始重试预算、多收件人持久化和取消竞态。因此复刻模型的“仅重发失败收件人”和发件箱归类仍为 P，不能冒充本机数据库行为。

机器结果：[sms-retry-rules.json](sms-retry-rules.json)，含全部命中比较路径。`sms_retry_decision` 只表达错误分支决策，不接入真实发送服务。

## 浏览器地址输入

地址提交入口 `88b65c54` 的完整短路径已核对：取控件 `60099` 的 UTF-16 文本，最多复制 512 个单元到清零的字节缓冲，调用 `883b4724` 检查；失败显示 `40000872`“Something's wrong with this URL.” 并保留编辑窗口；成功调用 `886b6218(1,url,null)` 后关闭地址窗口。新地址默认文本来自本机 `http://` 字面量。

复制函数 `883a51dc` 不是 UTF-8：遇到 NUL 或第一个大于 255 的 UTF-16 单元就停止有效复制、清零余下位置。所以 `http://example.invalid/中文` 在这个入口得到 ASCII 前缀。此调用路径没有参考源码可选 Punycode 分支的调用。

`883b4724` 只做窄检查：空串、首字节 >127、任一 CR/LF 为非法。CR/LF 字面量位于 `user+3b49d8`。范围比较用的是 `ldrb r1,[r5]`，不是 `r5+index`；因此该函数不会拒绝后续所有高位字节。空格、`http://` 这样的未完成地址也可通过此预检查，之后仍可能被引擎拒绝。

`browser_submit_address` 保留上述细节，返回服务动作，不联网。正式复刻若采用 UTF-8、IDNA、自动补协议或更严格校验，应明确作为 P，不能用现代 URL 库的默认行为替代后声称原样恢复。

## 浏览器认证

认证窗口 `60008` handler `88b62ce0`。列表行 2 打开用户名窗口 `60016`，行 4 打开密码窗口 `60017`；两字段描述的最大长度为 20。
