# 短信应用交互合同

关联 [本轮范围与证据等级](README.md)。主编辑窗口 `0x7000c`、handler `0x8839962a`；69 个消息组描述片段见 application-resources.json。短信与彩信共享编辑设施，出现附件项不能证明此地区具备可用 MMS 网络服务。

## 原生证据定位

| 编号 | 原生定位 | 能确认的行为 | 仍有限制 |
|---|---|---|---|
| S1 | `8839a0a0` 后的焦点比较，调用 `88398b7c` 或 `883988e0` | 左软键按收件人/正文焦点打开不同菜单 | 所有动态焦点规则未还原 |
| S2 | `8839a944..8839a9aa` | Cancel 检查当前控件是否为 `7007b`；是则隐藏候选列表、恢复 `70079`，否则走关闭 helper `88398098` | 其他弹层使用各自 handler |
| S3 | `8839ab80..8839ac56`、`88397db0..88397e04` | 关闭时有独立标志分支；未走该分支且正文非空时复制正文/收件人，调用保存路径，构造 `40000b84`“Saved”提示；空正文走清理 | 保存后的持久化失败/原子性未解析；不是所有关闭原因无条件保存 |
| S4 | `88399356..88399448` | 发送入口含收件人校验、偏好 SIM、电话簿 SIM 偏好及 SIM 选择逻辑 | 实际 SIM 就绪判定、偏好值枚举和所有异步结果未完整命名 |
| S5 | `8839c0bc..8839c0cc`、表 `user+39c0d0` | 137 项 u32 相对分发表；目标为 `8839c0d0 + entry[action]` | 表含默认项和共用项，不是 137 个独立功能 |
| S6 | `88398dd0`、表 `user+398dfc` | 14 项显示分支，进度和错误提示文本可恢复 | 这些是 UI 操作码，不是网络协议原因码 |
| S7 | `88399ffc` 起 | 收件人焦点进入联系人相关处理；正文路径检查收件人数、正文长度，再进入发送 | 中心/WEB 的物理接线仍没有实机闭合验证 |

`88398098` 设置的 normal-close 字节位于另一对象（`81d16394 + d57`），与 S3 检查的 `81c48784` 标志不是同一位置。不能因公共源码有 `GetNormalClose()` 就把两个标志合并；本机保存分支已改变。S3 保存 helper 的参数及调用形状与公共 `MMSSaveSms` 相关，函数名为 B。

| 4 | Insert smiley | 7 | `8839c5cc`，调用 `88172fb8` |
| 5 | Insert symbol | 7 | `8839c5d6`，调用 `88aa0776` |
| 6 | Insert template | 7 | `8839c5e0`，调用 `8864b42c` |
| 12 | Add attachments | 根 | 子菜单 |

| 32 | Save as draft | 根 | `8839c632` 发送 `e002` 给编辑窗口，转入关闭保存路径 |

构造顺序为 Insert options（smiley/symbol/template）、条件附件组、条件移除附件、Clear text、Save as draft。`88398b1c` 开始根据正文长度调整 Clear text；附件组还受 `88b0a19e` 的结果及地区 MCC 检查影响，不能无条件全部展示。原机“保存草稿”是退出编辑过程的一部分，不能做成点击后留在编辑页却声称原样复刻。

收件人菜单 `88398b7c` 添加 Contacts（`40000a83`）和 Groups（`40000a88`），再动态遍历组名。组内容来自用户数据，本项目没有读取。复刻用注入的合成联系人与组。

## 操作提示

完整原生 code/target/标签/偏移在 [sms-operation-status.json](sms-operation-status.json)。0 对应 Sending…；1 要求设置消息中心号码；2 提示将正确消息中心号码加入固定拨号号码列表；3 对应固定拨号限制；7 为 No space；其余已解析标签以 JSON 为准。5、6、8、9、10、11 在这个显示 helper 中进入日志/默认分支，13 委托另一函数，不能臆造对应提示。发送失败、SIM 取消与保存失败应作为独立服务事件，不能把 code 0 当成功。

## 复刻状态和数据

模型数据：文件夹、当前消息 ID、收件人数组、正文 UTF-16 单元、光标/选区、未提交多击候选、当前焦点、弹层、草稿 ID、SIM 选择、发送操作 ID、每收件人结果。文案、表情、模板、附件和输入模式不是同一对象。

| 当前状态 | 输入/条件 | 下一状态与动作 | 依据 |
|---|---|---|---|
| 文件夹 | 选择收件箱/草稿/发件箱/已发送 | 列表；保存列表焦点 | P-SMS-BOX；各类资源/窗口提供 A/B 存在线索 |
| 消息列表 | 选择收到/已发送消息 | 阅读；收到消息标记已读 | P-SMS-BOX |
| 阅读 | 回复 | 新编辑，填收件人，正文空 | C + P（精确引用规则未恢复） |
| 阅读 | 转发 | 新编辑，复制正文，收件人空 | P-SMS-BOX |
| 阅读/列表 | 删除 → 取消/确认 | 不变 / 删除且回列表 | P-SMS-BOX；确认和排序未按原机逐项验证 |
| 草稿列表 | 打开草稿 | 恢复同一草稿，保存时替换而非重复新增 | B + P-SMS-BOX |
| 编辑 | 左软键 | 按焦点开收件人菜单或正文菜单 | S1 |
| 编辑 | 收件人列表可见，返回 | 收起列表，回收件人输入，不退出正文 | S2 |
| 编辑 | 正文焦点、中心发送 | 缺收件人/正文不发送；其余进入 SIM/发送 | S7；模型的校验提示、焦点跳转为 P |
| 编辑 | 保存草稿/普通返回 | 先提交多击；执行关闭保存策略，回列表 | S2/S3/S5，普通关闭复刻默认条件见下文 |
| 编辑 | 多 SIM 无有效偏好 | SIM 选择；取消回原编辑状态 | S4 + P（偏好算法保持接口） |
| 发送中 | 重复发送键/返回 | 不重复提交；保留处理中状态 | P-SMS-SERVICE；原生取消语义未恢复 |
| 发送中 | 合成结果：全部成功 | 已发送列表；删除关联草稿 | P-SMS-SERVICE |
| 发送中 | 合成结果：全部失败/部分失败 | 成功收件人写已发送；仅失败收件人写发件箱；显示失败状态 | P-SMS-SERVICE；不是已恢复的原机多收件人策略 |

P-SMS-BOX：模型列表按递增本地 ID 倒序（不是原机时间排序证据）；正文非空退出默认保存，空的新草稿不创建；已有草稿被清空时当前参考模型保留之前的已保存副本，正式产品需明确是否删除原稿。真实存储失败必须保持编辑态并可重试，不能直接丢弃正文；当前内存模型没有磁盘失败适配器。

P-SMS-SERVICE：操作 ID 防重复提交/过期回调；每个收件人有结果，重试只针对失败者；本地号码校验仅 `+` 和数字，不代表原机完整地址解析。实际发送后端可用模拟服务，无需读取手机 SIM。

## 编辑细节

原生编辑核心、多击表和键盘映射沿用上一级 interaction-spec.md。模型补上“光标中间输入”“替换选区”“多击过程中替换同一候选”“移光标前提交候选”，测试均使用合成文本。

- 编辑位置必须是 UTF-16 单元索引。JS code point/字素簇下标不能直接与原生 `+ae` 字段等同。普通退格删一单元；原生某些范围对象支持删两单元，其完整判定仍未知，模型没有伪造代理项识别。
- 上下移动需要排版器给出可视行和光标 x/列位置；仅按 LF 切行无法模拟软换行。本轮模型仅用注入的行跨度验证流程，精确像素 x 保持仍是 renderer 接口。
- 数字多击表可直接复用已提取的 147 张表；已验证拉丁候选表 `0x21d592` 的 0 slot 包含空格/0/LF。`*` 符号、`#` 模式切换的完整跨模式状态仍需单独绑定。
- T9 词库已提取，但查询、词频和中文候选排序未解。可以给复刻系统接替代预测服务，但必须标 P，不能称 Nokia T9 已恢复。
- `e030` 名称是 EDITBOX_UPDATE_STRNUM，本机路径含收件人候选/匹配更新。**它不是已经证实的“正文短信计数公式入口”**；纠正之前过宽的描述。

短信 UI 公式、70/67 初始化和字符分类已恢复，见 [交互内核](interaction-core.md) 及 [原始字符表](sms-character-tables.json)。屏幕计数与发送分段分别建模。`sms_counter()` 返回原生分类/公式的 remaining/segments/text，当前编码配置仍是明确的复刻选择。

## 必测轨迹与剩余闭合点

已自动验证：同键/换键/提交；中间插入和选区；中文/双 UTF-16 字符偏移；160→161、70→71、扩展字符段边界；候选列表返回；草稿替换；缺收件人/无 SIM/选 SIM；重复发送/过期结果；部分失败；阅读/回复/转发/删除。

仍需原生闭合或实机轨迹：软键 Delete/Back 随编辑位置的精确变化、长按删除速率、输入法切换菜单、T9 候选翻页、实际短信容量/满存储、定时短信、MMS 自动转换、异常关闭与断电恢复、真实发送取消和运行时编码配置变化。模型实现完整的合成短信基本流，不覆盖这些未恢复功能。

## 新增原生规则

见 [本机算法](native-algorithms.md)：已恢复 8 组容量和分段 ESC 尾部处理、19 个重试原因码及错误处理优先级。普通 UCS2 内容路径明确以 UTF-16 单元数乘二记录字节长度。新增发送成功等待存储确认、写确认状态 1/3/4/5 的继续分支，以及失败长短信余段的保存规则。全部数据库归类和取消流程仍保持 P；局部纯规则见 [交互内核](interaction-core.md)。
