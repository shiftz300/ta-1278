## SFON：从查表到曲线

固件定位：加载 `0x88034076`、分段字形查找 `0x88033768`、字形元数据 `0x88033b2c`、简单轮廓 `0x8855f678`、组合轮廓 `0x8855fe64`、栅格化调用 `0x885602c2`。反汇编及输入 SHA 在 [code-analysis.json](code-analysis.json)。

1. 大端 SFON 头的 `+14` 为 strike 数；三份文件均为 1。`+18` 为单位值，分别 2048、1000、1000；`+40` 指向该 strike。
2. strike 的 34-byte 头中，`+26` 为字形数，`+32` 为分段数。之后依次为三个大端 u16 数组：段末 glyph ID、段首 glyph ID、起始索引。段数分别 48、5105、10667。
3. 命中的字形索引为 `start_index + gid - segment_start`。三个数组之后是大端 u32 偏移表；字形文件位置为 `strike_offset + 32 + stored_offset`。这解释了此前稀疏且数值很大的 glyph ID，并非映射损坏。
4. 字形首字节 bit 3 指示附加 advance；否则取 strike 默认值。bit 0 区分组合字形与简单轮廓。
5. 格式 3 的简单轮廓具有变长点数、轮廓数、重复标志压缩、X/Y 差分及轮廓终点索引。低位区分 on-curve，bit 6 表示 cubic 控制点。拉丁字体使用二次曲线；两份 hani 主要使用三次曲线。
6. 组合字形解析引用、偏移和缩放矩阵。606 个组合字形的被引用字形全部存在，无递归环；本机样本均为 XY 偏移形式。

输出 `*-outlines.json` 保存每个字形的 SFON 偏移、长度、坐标、标志、轮廓终点或组合参数；`*-glyphs.svg` 按 glyph ID 导出 symbol。三份 `.otf` 为本地转换的 CFF 字体，可加载到复刻项目。字体原件 `.sfon` 完整保留。

**OTF 的局限：** advance 按 SFON 标称 32 单位转换；没有恢复手机缩放、缓存、字体回退、基线布局或像素级栅格化一致性。二次轮廓转换为三次曲线用于 CFF。字体样张由已有 FreeType/Pillow 生成，已目视确认中英文字形可读；不是手机截图。

## BMP、SABM 与动画

新增 509 张 BMP `compression=0x1003`。RGB565 掩码明确为 `f800/07e0/001f`。每个 run 为两个字节 `(literal_count, repeat_count)`，先读 literal 个颜色，再读一个重复颜色并输出 repeat 次；`00 00` 结束一行。正高度按 BMP 自底向上转换。所有行宽、行数、输入结束位置均匹配，NOKIA 开机标志、箭头和输入法模式缩写经过目视检查。

初版误把重复像素放在 literal 之前，尺寸检查仍通过，但视觉明显错误。现已修正；保留此记录说明仅靠长度验证不足以确认图像正确。

49 个 SABM 未压缩条目恰有 `width × height × 4` 像素字节，已生成 BGRA 解释的预览；颜色通道顺序未完成原厂渲染器交叉确认。4 个 SMOV 的大端偏移表指向 ABMP；VM 则包含 4 个 `(size, offset)` 小端目录项，按目录顺序解码 RLE565。43 帧均通过边界与 PNG 加载检查。未把假定的帧间隔写成原生动画时间。

11 个 SJPG 现已重建 JPEG/PNG：量化表与 Huffman 表逐字节匹配本机 kernel，独立熵流遍历检查全部 MCU 和输入边界，联系表目视通过。剩余两个 `user` 名称记录为 `IMAGE_TITLE_BAR`、`IMAGE_COMMON_BG`，文件本身没有位图像素，其动态绘制路径仍未恢复。SMOV 的原始 interval 字段均为 24，单位未确认。详见 [最新格式证据](reverse-engineering-status.md)。

## 窗口、菜单和新建信息

窗口调试名称的注册例程 `0x88ab0718` 将组 8 关联到 `user+0x21b2a6`。查找代码 `0x885f237e..0x885f2392` 明确采用 `base + (low16(ID)-1) × 50`。组 7 的注册位于 `0x8879f9ec`，名称表基址 `user+0x227d60`。已据 28 处可识别的注册代码提取名称。

主菜单原有 30 项标签/图标/入口关联仍有效；实际排序、地区过滤和焦点移动尚未确认。CSCS 使用另一种编码：低 8 位为资源类别，高位为组，内部索引从 0 开始。不可把它和 API 的 1-based ID 混用。

消息编辑相关的实际描述：

| 窗口 ID | 原始名称 | 描述偏移 | Thumb 回调 |
|---|---|---|---|
| `0x7000c` | `MMIMMS_EDIT_MENU_WIN_ID` | `0x227790` | `0x8839962b` |
| `0x70010` | `MMIMMS_EDIT_TEXT_WIN_ID` | `0x2279ac` | `0x8839d7bb` |
| `0x70011` | `MMIMMS_EDIT_MAINMENU_OPT_WIN_ID` | `0x2278a8` | `0x8839bf5b` |
| `0x70026` | `MMIMMS_EDIT_MAINMENU_INSERT_OPT_WIN_ID` | `0x227900` | `0x8839e5b5` |

`0x7000c` 的标题引用 `0x400800e9`，实际三语言为 New message / 新建信息 / 新訊息；软键资源为 Option / 空 / Return。描述中含 11 个嵌套控件，根 ID `0x70071`；原始 opcode、参数及父子关系见 interaction-map。经公开框架关联，`0xa0` 是 EDIT_TEXT 构造时容量；11 节点类型和参数名已注释，不能等同于最终短信上限，像素几何仍未恢复。

处理函数既有 MMIMMS 标记也有 mmisms 日志，显示共用消息模块的线索；不能因此把全部 MMS 功能都视为本机 SMS 功能。已恢复 25 条原始事件到处理块的映射。例如 `0xe001` 与 `0xfa16` 都到 `0x8839a0a0`；`0xe002` 与 `0xfa17` 到 `0x88399ed4`；`0xe004` 与 `0xfa1b` 到 `0x883999da`。**新增原生按键转换表和公开框架关联，已命名 25 个事件并映射矩阵中的 19 个键；中心键硬件路径及每个处理块的全部副作用仍未恢复。**

此前容易混淆的 `0x80003` 实际对应 Voice mail 设置描述，不能当作短信正文编辑器。调试名称或函数附近出现 SMS 字样本身不足以证明调用关系。

## 可复用的输入行为

147 份字符表和已有键盘矩阵保持不变。新 [interaction_reference.py](../../tools/interaction_reference.py) 将已恢复的多击循环写成独立参考模型，输入是字符表 slot；显式 commit 表示已收到提交事件，不猜计时单位。

验证用例覆盖同键替换、换键提交、超时事件后同键追加、整圈回绕、`空格 → 0 → LF`、空 slot 不改变文本。它是恢复算法的说明，不是执行固件，也未冒充完整短信应用。见 [验证记录](interaction-reference-validation.json)。

已有原生证据还包括编辑缓冲 `+0x90`、长度 `+0x94`、光标 `+0xae`、选区 `+0xc2/+0xc4`，以及普通退格、带范围对象的删除和 LF 检测。SMS 底层分段出现 160/153、140/134 和段末 ESC 处理。不能直接把这些值等同于 UI 的中文字符计数，T9 内置词库块现已提取，英文及简体容器已重建；候选算法、繁体布局差异和编码选择仍未恢复。

## 验证与复现

运行已有 Python、Pillow、fontTools、Xcode LLVM 和 Node，未安装软件。五份系统组件 SHA 保持一致。汇总见 [validation.json](validation.json)：22,500 条文字逐字节回查、3 份 SFON 原始切片比较、147 个输入表、2,228 个 ABM PNG、612 个新增帧 PNG、2,824 项预览加载、22,349 个字形、3 份 OTF、751 段窗口原字节、1,357 个名称、73 个媒体文件全部通过对应校验。

在项目根目录运行：

```sh
python3 tools/rebuild_offline_ui.py
```

不连接手机，不执行固件。原始文件在 `firmware/original/`，所有派生产物在 `analysis/`。`SHA256SUMS` 记录稳定项目文件的 SHA-256。

## 尚未恢复的部分

当前完整清单见 [未恢复项](reverse-engineering-status.md#当前无法完成的逆向)。SJPG 已恢复；77 条单字节文本在 Latin-1/Windows-1252 下显示一致，其中三条的问号已存在于原始固件，无法唯一恢复原意。T9 原始块已提取，候选查询与排序未恢复。仍有字体像素度量、49 个 SABM 通道、动画时间单位、动态菜单/焦点/窗口栈、完整短信编辑状态、浏览器和其他应用全部行为等缺口。

现有结果可以复用字形、图标、文案、主题颜色、字符表和已核实的局部输入算法，不足以宣称完整原机交互复刻完成。所有公开源码名称关联均明确标注版本边界。
